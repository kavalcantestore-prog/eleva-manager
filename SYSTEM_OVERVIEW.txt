SECURITY FEATURES
================================================================================

Authentication
  - All routes require logged-in user (require_user())
  - User ID tracked in distribution records

Validation
  - Client must exist in database
  - contract_value must be > 0 (enforced in JS and backend)
  - Type checking on all numeric values

Authorization
  - Only authenticated users can initiate distribution
  - Backend validates user permission

Audit & Compliance
  - All actions logged with timestamp and user ID
  - Activity log provides full transaction history
  - Immutable records (append-only, no deletes)
  - No way to "undo" a distribution (intentional)

Data Integrity
  - Atomic transactions: INSERT + UPDATE together (all-or-nothing)
  - Foreign key constraints on client references
  - SQLite WAL mode for concurrent access safety

SUPPORT & TROUBLESHOOTING

Button Not Showing?

  - Refresh page (F5)

Distribution Failed?

  - Verify contract_value is valid number
  - Check network tab in browser dev tools
  - Review server logs (main.py output)

Values Incorrect?

  - Check database directly for rounding errors
  - All values stored as REAL (float), not INTEGER

Activity Not Logged?
  - Verify user_id is set correctly
  - Check activity_log table exists
  - Restart server if needed

  - Refresh page (F5)
